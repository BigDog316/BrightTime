## Conventions

**Keys.** `uuid` primary keys, **generated by the application as UUIDv7**
(`Guid.CreateVersion7()`). No `DEFAULT gen_random_uuid()` anywhere —
deliberately, so an accidental random v4 is a visible error rather than a
silent index-locality regression. High-volume append-only tables
(`outbox_message`, `listing_occurrence`, `search_event`, `import_row_error`,
and the analytics rollups) use `bigint generated always as identity`.

**Tenancy.** `tenant_id uuid not null` on every tenant-scoped table, FK to
`platform.tenant`. Child tables that lack it are protected through their
parent — the explicit list is layer 2 of `99-rls-and-grants.sql`.

**Timestamps.** `timestamptz` only, never `timestamp`. `created_at` /
`updated_at`, the latter maintained by `platform.touch_updated_at()`. Dates
that are genuinely calendar dates (`starts_on`, `expires_on`, `worked_on`) are
`date`.

**Concurrency.** Postgres `xmin` mapped as the EF rowversion. No manual
version columns.

**Status columns.** `text` with a named `CHECK` (see decision D5).
Tenant-configurable sets are lookup tables (`platform.taxonomy_term`).

**Soft delete.** Avoided. Lifecycle is an explicit status enum. Youth data is
hard-deleted on request, with the audit entry retained and pseudonymised
(open question Q5).

**Encryption.** Application AES-256-GCM, per-tenant data keys wrapped by a KEK
in `IKeyVault`. The `_enc bytea` suffix is a contract: the EF value converter
keys off it, and the Serilog destructuring policy refuses to serialise any
property whose name ends in `Enc`. Encrypted today: exact date of birth,
names in `family_member`, phone numbers, emergency contacts, support-need
detail, attendance notes, EIN, push tokens.

Equality lookup over an encrypted column uses an HMAC blind index
(`platform.blind_index`), not deterministic encryption, with the key held by
reference in `platform.blind_index_key` and rotation handled by a reindex job.

**No column for.** Youth home address or home coordinates. Background-check
reports, dispositions or case numbers. Cardholder data. Raw search query text.
Raw email or phone in `notify.delivery`. Collector GPS tracks. These absences
are the design; `docs/plan/07-threat-model.md` says why for each.

**Naming.** `pk_`, `fk_`, `ux_`, `ix_`, `ck_` prefixes; snake_case; singular
table names. Every constraint is named — an anonymous constraint produces an
error message nobody can act on.

## Six things worth looking at specifically

1. **`opportunity.listing_search`** (`40-opportunity.sql`) — the search read
   model, with the `facets text[]` design that collapses fourteen filter
   dimensions into one GIN index. Explained in `03-indexing-and-query-plans.md`.
2. **`community.enforce_safe_conversation()`** (`70-community.sql`) — the
   no-adult-minor-DM rule as a deferred constraint trigger plus
   `ck_conversation_minor_safety`. The safety rule is a database invariant,
   not a UI affordance.
3. **`identity.youth_access_grant`** (`20-identity.sql`) — time-boxed,
   reason-bearing provider access to a youth record. The table that stops a
   provider browsing youth it never served.
4. **`identity.enforce_child_consent()`** (`20-identity.sql`) — a child
   account cannot be active without an unrevoked `account` consent, as a
   deferred constraint trigger.
5. **`platform.audit_event`** (`10-platform.sql`) — one row per operation with
   `subject_ids uuid[]`, monthly range partitions created by
   `ensure_audit_partitions()`, append-only by both revoked grants and a
   statement trigger. See decision D11 for why per-operation and not per-record.
6. **`99-rls-and-grants.sql`, last block** — the assertion that raises and
   fails the migration if any module table has no row-level security. A new
   table without a policy becomes a deployment failure instead of a
   code-review miss.
